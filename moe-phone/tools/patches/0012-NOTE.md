# Patch 0012 — selective adoption of speculative expert reads (`--spec-adopt-selective`)

Applies to BigMoeOnEdge @ 74ba18f **after patches 0001–0011** (engine files only; no llama.cpp
submodule change). Default **off**; it is an A/B lever. Route-ahead behaviour is unchanged, and the
flag is rejected together with `--route-ahead`, and without a guessing predictor (`--predict-prefetch`
or `--prefetch K`).

## The defect it addresses

With a guessing predictor, every layer load runs `quiesce_spec()` destructively
(`core/src/moe/expert_stream_source.cpp`): it bumps the speculation generation, clears the queue,
waits for reads in flight, integrates only the entries whose every projection had finished, and
releases the pages of every other entry. A correct guess that the lanes had not finished within one
layer of compute (~2.8 ms on the 15R) is therefore thrown away and read again on demand. The source's
own comment records the outcome it was fixed for under `--route-ahead` only: "every early read was
destroyed ... for 0% useful and double flash per token". `settle_spec()` runs the same destructive
quiesce before the drop, substitution and trace paths.

On the phone (`results/2026-09-17/bmoe_boost/predpf_rep*.out`): 3.9 GB speculative per 256 tokens, 802
experts integrated of which 563 were used, i.e. about half the speculative bytes went into entries that
were released unfinished.

## What the flag does

At layer L's load the engine already holds L's true routed ids. `quiesce_selective()` uses them:

| speculative entry | action |
|---|---|
| layer L, chosen by the router (confirmed) | adopt: jobs move to the front of the queue, the load waits for the entry, it integrates **hot** and the staging sees a hit |
| layer L, not chosen, no read started | cancel: jobs removed under `io_mtx_`, pages released |
| layer L, not chosen, a read already started | left to finish; integrates at the cold end like any guess |
| any other layer | untouched |

`settle_spec()` becomes integrate-only in this mode, and the forget-on-failure path in `drain_spec()`
covers it too (a failed read cannot park the adoption wait).

Why the release is safe: `spec_remaining_[id]` counts an entry's unfinished jobs. When it equals the
number of that entry's jobs still in the queue, none is in flight, and lanes take jobs only under
`io_mtx_`, which is held while the jobs are removed.

Lossless by construction: it changes only when bytes arrive, never which experts compute or with
what bytes (the same gate G10 argument as `--prefetch`). Checked below by comparing generated text.

## Telemetry

A shutdown line on stderr: `bmoe: spec-adopt-selective: quiesces Q adopted A cancelled C (X MiB unread)
left-to-finish F`. The existing `moe-prefetch:` line still reports speculative MiB and
useful/integrated experts; the adoption wait is in the existing `adopt_ms` CSV column.
