# Patch 0013 — confidence gates on predictive speculation (`--predict-spec-rank`, `--predict-spec-margin`)

Applies to BigMoeOnEdge @ 74ba18f **after patches 0001–0012** (engine files only). Both gates are
**off by default**; with them off, `build_spec_lists` produces exactly the 0012 lists. The gates only
remove experts from the speculation list, so the computation and its output are unchanged
(lossless, same argument as `--predict-prefetch` itself).

## Why

The 0012 phone A/B (`results/2026-09-18/specadopt_summary.json`, commit a01573f; Latin ×3, 9/9 identical
text) showed selective adoption working as designed and exposed the next limiter:

| arm | useful spec experts/token | stall | read MiB/token | cache mgmt |
|---|---|---|---|---|
| base | – | 45 ms | 119.8 | 19 ms |
| predict-prefetch | 3.1 | 45 ms | 140.3 | 28 ms |
| + spec-adopt-selective | 7.0 | 36 ms | 130.7 | 24 ms |

`cancelled = 0` in every run, with 650–700 entries left to finish. Every refuted guess had already
started reading by the time its layer loaded, so the refuted bytes (130.7 − 119.8 = 10.9 MiB/token)
are paid at **issue** time. The only place to stop paying them is the issue decision.

## What the gates do

The predictor ranks layer L's predicted top-k from a stale gate input. Of the predicted misses (not
resident), up to `--predict-spec-max` are speculated in rank order. The gates remove a predicted miss
before that cap applies:

- `--predict-spec-rank R` (0 = off): speculate only if its predicted rank among the top-k is < R.
- `--predict-spec-margin M` (< 0 = off): speculate only if `(score − boundary) / sd ≥ M`. Here
  `boundary` is the score of the best predicted expert outside the top-k, and `sd` is the standard
  deviation of that layer's predicted scores over all experts, which makes `M` scale-free across
  layers. A small margin marks an expert at the top-k edge. That is where a two-layer-stale input
  most often reorders the ranking.

Residents are still retained (LRU-protected) whatever the gates say, because retention costs no bytes.

Shutdown telemetry on stderr, printed only when a gate is on:
`bmoe: predict-gate: rank<R margin>=M | predicted misses N, cut by rank a, by margin b, by spec-max c, issued d`.
Along with 0012's `spec-adopt-selective:` line and the `moe-prefetch:` line, this gives issue
precision directly: useful ÷ issued.

## Verification done (laptop; no model run, per the memory rules)

- builds (Release, `-j2`, memory-capped); `bmoe_config_test` passes;
- validation: `--predict-spec-rank` outside [0, 8] is rejected, and either gate is rejected without
  `--predict-prefetch` (under `--moe-stream`, where all MoE options are validated);
- `0013-test-build-spec-lists.cpp` is a standalone unit test of the list builder. It is not part of
  the patch; it builds against a 0013 tree with `#define private public`. All 6 checks pass: gates
  off equals the old list, the rank gate keeps ranks < R, the margin gate cuts only the top-k edge
  expert, residents are retained regardless, the spec-max cap still applies, and the counters add up;
- applies cleanly (`git apply --check`) on 74ba18f + 0001–0012.

## Pre-registered phone sweep (fixed before any gated row exists)

Base flags as the 0012 A/B: pinned t4 / io4, 5000 MiB cache, `--predict-prefetch --predict-spec-max 3
--spec-adopt-selective`. Arms, rotated Latin × 3, text identity checked per row:

| arm | gate |
|---|---|
| sel | none (the 0012 reference) |
| r1 | `--predict-spec-rank 1` |
| r2 | `--predict-spec-rank 2` |
| m05 | `--predict-spec-margin 0.5` |
| m10 | `--predict-spec-margin 1.0` |

Plus `base` (no prefetch) for the byte and stall reference.

**Primary quantities** (clock-independent first): issued and useful speculative experts per token,
issue precision (useful ÷ issued), read MiB/token, then the stall term, then wall time last.

**Decision rule, stated before the run.** A gated arm is preferred over `sel` if it removes at least
half of `sel`'s excess bytes over `base` while keeping at least 80% of `sel`'s stall reduction over
`base`, **evaluated against this sweep's own `sel` and `base` medians** (corrected 2026-09-18, before
any gated row, at the phone session's catch: the 0012 reference ran at `--predict-spec-max 2`, this
sweep at 3). The absolute figures from the 0012 run (read ≤ 125.3 MiB/token, stall ≤ 37.8 ms) are
reported alongside, as secondary. See the header of `device/bmoe_specgate.sh`. If no arm meets
both, the gates are reported as not helping, and the whole grid is published either way. The
thresholds were chosen from the 0012 reference, not from any gated row (`CLAUDE.md` §6.4). The grid
values (ranks 1–2, margins 0.5–1.0 sd) are round values picked before seeing the score distribution,
not fitted.

No magnitude is predicted, because the predicted-score distribution on Qwen3-30B-A3B has never been
logged. The expected direction is fewer bytes, fewer useful experts per token, and higher precision.

## A further lever, not drafted

Refuted entries that are only partly read could have their unstarted projections cancelled
(job-granularity instead of entry-granularity cancel), releasing the entry once its in-flight job
lands. The bound from the 0012 counters: ~2.6–2.7 refuted entries per token left to finish, of which
at most 2 of 3 projections could still be unstarted, which is ≤ ~4.7 MiB/token of the 10.9. Worth
drafting only if the gates leave a byte excess the rule above calls material.
